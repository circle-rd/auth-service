Auth Service is configured with environment variables only. They are validated by [Zod](https://zod.dev/) when the process starts: a missing or malformed value stops the startup with a message listing every failing field.

This page covers the decisions you take for a new deployment. Every variable, with its default, is listed in the [environment variables reference](/docs/reference/environment-variables).

## The three required values

| Variable | Description |
|---|---|
| `BETTER_AUTH_SECRET` | Random secret (16 characters minimum). Generate it with `openssl rand -base64 32` |
| `BETTER_AUTH_URL` | Public base URL of the service, for example `https://auth.example.com`. It is the OIDC `issuer` and the base of every link sent by e-mail |
| `DATABASE_URL` | PostgreSQL connection URL. The Compose file builds it from `POSTGRES_USER`, `POSTGRES_PASSWORD` and `POSTGRES_DB` |

::callout{icon="i-lucide-triangle-alert" color="warning"}
`BETTER_AUTH_URL` must be the URL your users and client applications reach. Tokens carry it as `iss`, and resource servers compare it with the issuer they trust.
::

## First administrator

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` before the first start. A superadmin is created when none exists; later starts do nothing. The password needs at least 12 characters, and the placeholder from `.env.example` is refused.

## Browsers, cookies and proxies

| Variable | Use it when |
|---|---|
| `CORS_ORIGINS` | A browser application calls the API from another origin. Origins of registered applications are added at runtime, see [Protected resources and CORS](/docs/concepts/runtime-config) |
| `SESSION_DOMAIN` | Applications on sibling sub-domains must share the session cookie (`example.com` for `auth.example.com` and `app.example.com`) |
| `TRUST_PROXY_HOPS` | The service sits behind a reverse proxy. Set it to the number of proxies (usually `1`), otherwise rate limits see the proxy address instead of the client address. The default `0` ignores `X-Forwarded-For` |

## E-mail

In production, e-mail verification is required by default, so `SMTP_HOST` must be set before the service starts. Either configure SMTP (see [Email setup](/docs/guides/administration/email-setup)) or opt out explicitly with `REQUIRE_EMAIL_VERIFICATION=false`.
