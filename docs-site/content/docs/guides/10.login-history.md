# Login history

Auth Service records every successful login in the `login_history` table. This provides an audit trail of all authentication events across the platform.

## Data model

| Field | Type | Description |
|---|---|---|
| `id` | UUID | Primary key |
| `userId` | string | User identifier |
| `applicationId` | string \| null | Application slug (null for direct admin dashboard sign-in) |
| `sessionId` | string \| null | Associated session ID |
| `ipAddress` | string \| null | Client IP address (from `X-Forwarded-For`) |
| `userAgent` | string \| null | Client user-agent string |
| `loggedAt` | timestamp | Login timestamp (UTC) |

## How it works

Every successful login triggers an insert into `login_history` and updates the denormalised `user.last_login_at` timestamp. The write is wrapped in a try/catch in the token-issuance hot path — failures are logged at warn level but do not block authentication.

## Admin API endpoints

### List login history for a user in an application

```
GET /api/admin/applications/:id/users/:userId/history
Authorization: Bearer <admin_session>
```

Returns paginated login history for the specified user within the specified application:

```json
{
  "logins": [
    {
      "id": "uuid-1",
      "ipAddress": "192.168.1.1",
      "userAgent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)...",
      "loggedAt": "2026-06-15T14:30:00Z"
    },
    {
      "id": "uuid-2",
      "ipAddress": "10.0.0.1",
      "userAgent": "Mozilla/5.0 (Macintosh; Intel...)",
      "loggedAt": "2026-06-14T09:15:00Z"
    }
  ],
  "total": 42,
  "page": 1,
  "limit": 20
}
```

### Query parameters

| Parameter | Default | Description |
|---|---|---|
| `page` | `1` | Page number |
| `limit` | `20` | Results per page (max 100) |

## Admin dashboard

The admin dashboard includes a **login history** panel on the user detail view (`/admin/users/:id`). It shows the last 20 logins with IP address, user-agent, and timestamp.

## Statistics endpoint

The platform-wide login statistics endpoint provides a dense daily series:

```
GET /api/admin/stats/logins?range=7d|30d&appId=<uuid>
Authorization: Bearer <admin_session>
```

Response:

```json
{
  "logins": [
    { "date": "2026-06-11", "count": 42 },
    { "date": "2026-06-12", "count": 38 },
    { "date": "2026-06-13", "count": 55 },
    { "date": "2026-06-14", "count": 61 },
    { "date": "2026-06-15", "count": 47 },
    { "date": "2026-06-16", "count": 33 },
    { "date": "2026-06-17", "count": 28 }
  ]
}
```

| Parameter | Default | Description |
|---|---|---|
| `range` | `7d` | Time range: `7d` or `30d` |
| `appId` | — | Filter by application UUID |

The series is **dense** — days with no logins are filled with `count: 0` so chart libraries render a continuous axis.

## Use cases

- **Security auditing** — detect unusual login patterns (geographic anomalies, unusual user-agents).
- **Compliance** — maintain an audit trail of all authentication events.
- **Analytics** — track login trends over time via the statistics endpoint.
- **Forensics** — investigate compromised accounts by reviewing login history.
