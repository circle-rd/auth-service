Auth Service is designed to work seamlessly with [Model Context Protocol (MCP)](https://modelcontextprotocol.io) servers. Any MCP client can authenticate via OAuth 2.1 Authorization Code + PKCE and receive a JWT access token containing roles, permissions, feature flags, and organization claims.

## Architecture

```
MCP Client (Claude, Cursor, etc.)
        │
        │  OAuth 2.1 Authorization Code + PKCE
        ▼
┌──────────────────────┐
│   auth-service       │  ← Identity Provider
│   (BetterAuth core)  │
└──────────┬───────────┘
           │  JWT access token
           ▼
┌──────────────────────┐
│  MCP Server          │  ← Resource Server
│  (your MCP backend)  │  verifies JWT via JWKS
└──────────────────────┘
```

The MCP server verifies tokens using the public JWKS endpoint — no shared secret is required.

## Step 1 — Register your MCP server as an application

Create a **public** application in auth-service (MCP clients are public/PKCE-only):

```sh
POST /api/admin/applications
Content-Type: application/json

{
  "name": "My MCP Server",
  "slug": "my-mcp-server",
  "description": "MCP server for document management",
  "isPublic": true,
  "allowedScopes": ["openid", "profile", "email", "roles", "permissions", "features", "org"],
  "redirectUris": ["https://mcp.example.com/callback"],
  "isMfaRequired": false
}
```

Key fields:
- `isPublic: true` — no client secret needed; PKCE is required
- `allowedScopes` — include `roles`, `permissions`, `features`, and `org` to receive all claims
- `redirectUris` — the callback URL your MCP client will use

## Step 2 — MCP client authentication flow

### Authorization URL

Construct the authorization URL with PKCE:

```typescript
// 1. Generate PKCE verifier and challenge
const verifier = generatePKCEVerifier(); // 43-128 random chars
const challenge = await generatePKCEChallenge(verifier); // S256

// 2. Build authorization URL
const authorizeUrl = "https://auth.example.com/api/auth/oauth2/authorize";

const params = new URLSearchParams({
  client_id: "my-mcp-server",           // application slug
  response_type: "code",
  redirect_uri: "https://mcp.example.com/callback",
  scope: "openid profile email roles permissions features org",
  resource: "https://mcp.example.com",  // must match the application's url (its protected resource)
  code_challenge: challenge,
  code_challenge_method: "S256",
});

window.location.href = `${authorizeUrl}?${params}`;
```

### Token exchange

After the user authenticates and consents, the MCP client exchanges the code for a JWT:

```typescript
const tokenResponse = await fetch("https://auth.example.com/api/auth/oauth2/token", {
  method: "POST",
  headers: { "Content-Type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({
    grant_type: "authorization_code",
    code: "<authorization_code_from_callback>",
    redirect_uri: "https://mcp.example.com/callback",
    client_id: "my-mcp-server",
    code_verifier: verifier,  // PKCE verifier
  }),
});

const { access_token, id_token, refresh_token } = await tokenResponse.json();
```

The `access_token` is a signed JWT containing custom claims.

## Step 3 — MCP server JWT verification

### JWKS endpoint

```
GET https://auth.example.com/api/auth/jwks
```

Returns the public key set. Keys are Ed25519, so verify with `EdDSA`:

```json
{
  "keys": [
    {
      "kty": "OKP",
      "crv": "Ed25519",
      "alg": "EdDSA",
      "kid": "key-id-here",
      "x": "..."
    }
  ]
}
```

### Verify the JWT

Use a JOSE library that fetches and caches the key set by `kid`, such as [`jose`](https://github.com/panva/jose):

```typescript
import { createRemoteJWKSet, jwtVerify } from "jose";

const JWKS = createRemoteJWKSet(new URL("https://auth.example.com/api/auth/jwks"));

async function verifyMcpToken(bearerToken: string): Promise<JwtPayload> {
  const { payload } = await jwtVerify(bearerToken, JWKS, {
    algorithms: ["EdDSA"],
    issuer: "https://auth.example.com",
    audience: "https://mcp.example.com", // the application's url (its protected resource)
  });

  return payload as JwtPayload;
}

interface JwtPayload {
  sub: string;           // User ID
  aud: string[];         // The resource URL the token was issued for (plus the userinfo endpoint)
  iss: string;           // https://auth.example.com
  azp: string;           // client_id of the application that obtained the token
  exp: number;           // Expiration timestamp
  iat: number;           // Issued at timestamp
  roles?: string[];      // ["admin", "editor"]
  permissions?: string[]; // ["documents", "documents.write"]: "resource" = read, "resource.write" = write
  features?: Record<string, unknown>; // {"maxProjects": 50, "apiAccess": true}
  org_id?: string;       // Active organization ID (if org scope requested)
  email?: string;
  email_verified?: boolean;
  name?: string;
  picture?: string;
}
```

## Step 4 — Use claims in MCP handlers

### Example: MCP server with role-based access

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = new McpServer({
  name: "my-mcp-server",
  version: "1.0.0",
});

// Middleware to extract and verify JWT
async function withAuth<T extends Parameters<McpServer["tool"]>[1]>(
  handler: T
): Promise<T> {
  return async (args, context) => {
    const authHeader = context?.headers?.authorization;
    if (!authHeader?.startsWith("Bearer ")) {
      throw new Error("Missing or invalid authentication");
    }

    const payload = await verifyMcpToken(authHeader.slice(7));

    // Check roles
    if (!payload.roles?.includes("editor")) {
      throw new Error("Insufficient permissions: requires 'editor' role");
    }

    // Check feature flags
    if (payload.features?.["apiAccess"] !== true) {
      throw new Error("API access not available on your plan");
    }

    // Check organization scope
    if (payload.org_id) {
      // Scope all queries to this organization
      args.orgId = payload.org_id;
    }

    return handler(args, { ...context, user: payload });
  } as T;
}

// MCP tool with authentication
server.tool(
  "documents.list",
  "List documents for the authenticated user",
  {
    orgId: z.string().optional(),
    page: z.number().default(1),
  },
  withAuth(async (args, context) => {
    const userId = context.user.sub;
    const orgId = args.orgId ?? context.user.org_id;

    const documents = await db.documents.findMany({
      where: {
        orgId: orgId,
        userId: userId,
      },
      limit: 20,
      offset: (args.page - 1) * 20,
    });

    return {
      content: [{ type: "text", text: JSON.stringify(documents, null, 2) }],
    };
  })
);

// Start the MCP server
const transport = new StdioServerTransport();
await server.connect(transport);
```

### Example: MCP tool with feature flag gating

```typescript
server.tool(
  "export.generate",
  "Generate an export of user data",
  {
    format: z.enum(["pdf", "csv", "json"]).default("json"),
  },
  withAuth(async (args, context) => {
    const features = context.user.features ?? {};

    // Gate on feature flag
    if (features["exportEnabled"] !== true) {
      return {
        content: [{
          type: "text",
          text: JSON.stringify({
            error: "Export not available on your plan",
            upgradeUrl: "https://auth.example.com/upgrade",
          }),
        }],
      };
    }

    // Gate on plan tier
    const maxExports = features["maxExports"] ?? 0;
    const usedExports = features["exportsUsed"] ?? 0;
    if (usedExports >= maxExports) {
      return {
        content: [{
          type: "text",
          text: JSON.stringify({
            error: "Export limit reached",
            remaining: maxExports - usedExports,
          }),
        }],
      };
    }

    // Proceed with export
    const exportData = await generateExport(context.user.sub, args.format);
    return {
      content: [{ type: "text", text: JSON.stringify(exportData) }],
    };
  })
);
```

## Step 5 — Token refresh

When the access token expires, use the refresh token to obtain a new one:

```typescript
const refreshResponse = await fetch("https://auth.example.com/api/auth/oauth2/token", {
  method: "POST",
  headers: { "Content-Type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({
    grant_type: "refresh_token",
    refresh_token: "<refresh_token>",
    client_id: "my-mcp-server",
  }),
});

const { access_token: newAccessToken, refresh_token: newRefreshToken } =
  await refreshResponse.json();
```

## Step 6 — Client credentials grant (server-to-server)

For MCP servers that need to authenticate as themselves (not as a user). This needs a **confidential** application: public applications cannot use the `client_credentials` grant.

```typescript
const basic = Buffer.from(`my-mcp-server:${process.env.MCP_CLIENT_SECRET!}`).toString("base64");
const tokenResponse = await fetch("https://auth.example.com/api/auth/oauth2/token", {
  method: "POST",
  headers: {
    "Content-Type": "application/x-www-form-urlencoded",
    Authorization: `Basic ${basic}`, // HTTP Basic, not client_secret in the body
  },
  body: new URLSearchParams({
    grant_type: "client_credentials",
    resource: "https://mcp.example.com",
  }),
});

const { access_token } = await tokenResponse.json();
```

The resulting JWT will have:
- `sub` = application slug (not user ID), and `scope` = `m2m`
- `aud` = the resource URL
- No `roles`, `permissions`, or `features` claims (these are user-specific)

## Complete integration example

### MCP client (TypeScript)

The authorization-code flow of an MCP client is the one described in [Integrating a third-party application](/docs/guides/integration/third-party-app): discovery, PKCE, `resource=<your MCP server URL>`, then a `Bearer` header on every MCP request.

### MCP server (Python)

```python
import jwt  # PyJWT: pip install "pyjwt[crypto]"
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("my-mcp-server")

# PyJWKClient caches the key set and refetches it when it meets an unknown kid
jwks_client = jwt.PyJWKClient("https://auth.example.com/api/auth/jwks")

def verify_token(bearer_token: str) -> dict:
    """Verify JWT and return payload."""
    signing_key = jwks_client.get_signing_key_from_jwt(bearer_token)
    return jwt.decode(
        bearer_token,
        signing_key.key,
        algorithms=["EdDSA"],
        issuer="https://auth.example.com",
        audience="https://mcp.example.com",
    )

@mcp.tool()
async def list_documents(page: int = 1) -> str:
    """List documents for the authenticated user."""
    # Extract from MCP context headers
    auth_header = mcp.context.headers.get("authorization", "")
    if not auth_header.startswith("Bearer "):
        raise ValueError("Authentication required")

    payload = verify_token(auth_header[7:])

    # Check roles
    if "editor" not in (payload.get("roles") or []):
        raise PermissionError("Requires 'editor' role")

    # Check feature flags
    features = payload.get("features") or {}
    if not features.get("apiAccess"):
        raise PermissionError("API access not available on your plan")

    # Scope by organization
    org_id = payload.get("org_id")
    user_id = payload["sub"]

    documents = await db.documents.find_many(
        where={"org_id": org_id, "user_id": user_id},
        limit=20,
        offset=(page - 1) * 20,
    )
    return json.dumps(documents, indent=2)
```

## Discovery

All configuration parameters can be auto-discovered from:

```
GET https://auth.example.com/.well-known/openid-configuration
```

Excerpt of the response:


## Security considerations

1. **Always use PKCE** — MCP clients are public clients; PKCE is mandatory.
2. **Validate `aud` and `iss`** — ensure the token was issued for your MCP server.
3. **Cache JWKS keys** — fetch and cache JWKS keys; refresh periodically (e.g., every hour).
4. **Check token expiration** — verify `exp` claim before using the token.
5. **Use HTTPS** — all OAuth endpoints must be accessed over HTTPS.
6. **Store secrets securely** — client secrets (for confidential clients) should be stored in environment variables or a secrets manager, never in code.
7. **Scope minimization** — only request the scopes your MCP server actually needs.
