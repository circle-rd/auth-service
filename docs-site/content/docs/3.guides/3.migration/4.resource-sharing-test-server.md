---
title: Migrating a test server to the generic resource schema
description: Preserve the OIDC applications of a pre-production auth-service database when the consolidated resource-sharing baseline replaces the legacy sharing tables.
---

The generic resource-sharing migration replaces `shared_resource`,
`resource_grant`, `resource_invitation` and `usage_record` with
`resources`, `resource_schemes`, `application_schemes`, `resource_grants`,
`resource_invitations`, `resource_access_events`, `resource_usage_records`,
`gateway_objects`, `resource_gateway_links` and the SSH tables.

This runbook is for a **test server** with OIDC applications but no sharing
data worth preserving. It recreates the database from the new consolidated
baseline, then restores the stable application, user, client, plan and wallet
rows. It is not a production migration: after the first production deploy,
migrations are immutable and a new `NNNN_*.sql` is required.

::callout{icon="i-lucide-triangle-alert" color="warning"}
Take a full dump before touching the server. Never run this against a database
that contains sharing rows you need. Never paste secrets into a ticket or a
chat.
::

## 1. Stop writers

```bash
docker compose --profile <profiles> stop auth-service
```

Keep PostgreSQL running so the dump and restore can use it.

## 2. Dump the stable data

```bash
docker compose exec -T postgres sh -c '
  pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
    --data-only \
    --exclude-table=__drizzle_migrations \
    --exclude-table=shared_resource \
    --exclude-table=resource_grant \
    --exclude-table=resource_invitation \
    --exclude-table=usage_record
' > auth-service-data-only.sql
```

Keep the dump outside the repository (or in a gitignored path).

## 3. Recreate the schema

```bash
docker compose exec -T postgres sh -c '
  dropdb -U "$POSTGRES_USER" "$POSTGRES_DB" &&
  createdb -U "$POSTGRES_USER" "$POSTGRES_DB"
'
docker compose run --rm auth-service node dist/migrate.js
```

The consolidated baseline is `drizzle/0000_initial_schema.sql`. Do not create
`0001_*.sql` for a pre-production reset.

## 4. Restore the stable data

```bash
docker compose exec -T postgres sh -c '
  psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1
' < auth-service-data-only.sql
```

The dump contains applications, users, OAuth clients, plans, subscriptions,
wallets and their related rows. It excludes only the four legacy sharing
tables.

## 5. Verify

```bash
docker compose up -d auth-service
curl -fsS http://localhost:3001/health
```

Then check in the dashboard:

- the OIDC applications are listed with their client ids and redirect URIs;
- an existing application can complete an authorization code flow;
- no legacy sharing row is expected;
- `RESOURCE_SCHEMES_ENABLED` is set only for the schemes whose services are
  running.

## 6. Re-enable sharing deliberately

1. Keep `RESOURCE_SHARING_ENABLED=false` until the new screens are reviewed.
2. Enable a platform scheme (`llm`, `agent`, `mcp`, `ssh`) in
   `RESOURCE_SCHEMES_ENABLED`.
3. Enable it per application in **Application → Sharing**.
4. Create and validate resources, then grant them.

## Rollback

If the restore fails, drop the recreated database and restore the full dump
taken in step 1. The legacy sharing rows are in that dump; they are only
useful to return to the previous code.
