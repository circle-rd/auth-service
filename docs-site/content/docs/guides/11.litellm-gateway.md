# LiteLLM gateway

auth-service ships an optional [LiteLLM](https://docs.litellm.ai/) proxy behind
the Docker Compose profile `llm`. Applications obtain an auth-service access
token for the gateway and call LiteLLM with it; no per-user API key is issued.

> Credits are held by the [wallet API](/docs/reference/api-reference); the
> gateway hook that calls it is still to come: see the
> [programme plan](/docs/project/litellm-wallet-plan).

## How authentication works

LiteLLM's built-in JWT auth is an Enterprise feature, so the gateway validates
tokens in `litellm/custom_auth.py` (wired through `general_settings.custom_auth`):

- the signature is checked against the auth-service JWKS (`/api/auth/jwks`, EdDSA);
  an unknown `kid` triggers one refetch per 30 seconds, so key rotation is picked up;
- `iss` must equal `BETTER_AUTH_URL` and `aud` must contain `LITELLM_PUBLIC_URL`;
- `client_credentials` tokens are rejected (they carry no user: `sub` equals `azp`);
- the user is the token `sub`, the calling application is `azp`;
- `LITELLM_MASTER_KEY` still works for administration.

The gateway is registered as an application (`litellm`) whose `url` is the
resource identifier (RFC 8707). A client application receives a JWT only when it
sends `resource=<LITELLM_PUBLIC_URL>` **and** lists that URL in its
[`allowedResources`](/docs/concepts/runtime-config). Public (PKCE) and
confidential applications are both supported.

## Setup

1. Set the public URL of the gateway in `.env` (it is the token audience):

   ```sh
   LITELLM_PUBLIC_URL=https://llm.example.com
   ```

2. Generate the secrets and register the gateway application. `--grant` lists
   the applications allowed to request LiteLLM tokens (optional, repeatable later):

   ```sh
   pnpm llm:setup -- --grant=my-app,my-other-app
   ```

   The script signs in with `ADMIN_EMAIL` / `ADMIN_PASSWORD` (a superadmin),
   writes `LITELLM_MASTER_KEY` and `LITELLM_SALT_KEY` into `.env` if they are
   empty (existing values are never overwritten) and is safe to re-run. It also
   registers the `litellm-wallet` machine application with the `wallet:debit`
   and `wallet:read` scopes and keeps its secret in
   `LITELLM_WALLET_CLIENT_SECRET`: a missing or rejected secret (for example
   after recreating the database) is rotated. Never change
   the salt key once models have been added: it encrypts the provider credentials.

3. Start the stack with the profile:

   ```sh
   docker compose --profile llm up -d
   ```

   `litellm-db-init` creates the `litellm` database next to the auth one, then
   `litellm` starts once auth-service is healthy.

4. Verify the whole chain:

   ```sh
   pnpm llm:smoke
   ```

   The smoke test creates two temporary applications (public and confidential)
   and a mock model, then checks that user tokens are accepted and that
   `client_credentials`, wrong-audience, tampered, malformed and missing tokens
   are rejected, and exercises the wallet API with the gateway credentials
   (authorization checks only, no ledger entry is written). Everything it
   creates is deleted afterwards.

## Adding models

Models are stored in the LiteLLM database, so no provider key lives in the
repository. Use the LiteLLM admin UI or `POST /model/new` with the master key.

## Variables

| Variable | Default | Description |
|---|---|---|
| `LITELLM_PUBLIC_URL` | — | Public URL of the gateway; access-token audience and `url` of the `litellm` application |
| `LITELLM_URL` | `LITELLM_PUBLIC_URL` | URL the smoke test calls, when different from the public one |
| `AUTH_SERVICE_URL` | `BETTER_AUTH_URL` | URL the scripts use to reach auth-service |
| `LITELLM_MASTER_KEY` | generated | LiteLLM admin key |
| `LITELLM_SALT_KEY` | generated | Encrypts provider credentials in the LiteLLM database |
| `LITELLM_WALLET_CLIENT_SECRET` | generated | Secret of the `litellm-wallet` machine client (client id `litellm-wallet`) used to call the wallet API |
| `LITELLM_PORT` | `4000` | Host port published by the `litellm` service |
| `LITELLM_IMAGE` | `ghcr.io/berriai/litellm:v1.104.2` | Pinned image; re-run `pnpm llm:smoke` before bumping it |

## Troubleshooting

| Symptom | Cause |
|---|---|
| `/authorize` redirects with `invalid_target` | The application does not list the gateway URL in `allowedResources` |
| Access token is opaque (not a JWT) | The authorization request omitted `resource` |
| `401 Invalid or expired access token` | Wrong `iss`/`aud` (check `BETTER_AUTH_URL` and `LITELLM_PUBLIC_URL`), expired token, or JWKS unreachable from the container |
| `litellm` exits at start | A required variable is empty: run `pnpm llm:setup` |
