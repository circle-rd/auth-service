title: Email setup
description: Configure SMTP for verification, password reset, magic link, one-time code and invitation e-mails.
---

Auth Service sends e-mail with [Nodemailer](https://nodemailer.com). E-mail is required whenever a flow that depends on it is active, and in production that is the case by default.

## Configuration

```sh
SMTP_HOST=smtp.example.com
SMTP_PORT=587                  # defaults to 587
SMTP_USER=user@example.com
SMTP_PASS=your-smtp-password
SMTP_FROM=Auth Service <no-reply@example.com>
MAIL_REPLY_TO=support@example.com   # optional
```

Port `465` uses implicit TLS; every other port uses STARTTLS negotiation. When `SMTP_USER` and `SMTP_PASS` are empty, Nodemailer connects without authentication, which suits a local relay.

## When SMTP is mandatory

In production (`NODE_ENV=production`, which the Compose stack forces):

- `REQUIRE_EMAIL_VERIFICATION` is **on by default**: a user cannot sign in before following the link sent to their address.
- `MAGIC_LINK_ENABLED` and `EMAIL_OTP_ENABLED` add passwordless sign-in by e-mail, for existing accounts only. Both are off by default.
- If any of these three is on and `SMTP_HOST` is empty, the process **refuses to start**.
- At startup the SMTP connection is checked, and a failure is fatal. Outside production it is only logged as a warning.

To run a production instance without e-mail, set `REQUIRE_EMAIL_VERIFICATION=false` explicitly. Without SMTP, e-mails are then dropped with a log line, which also means users cannot reset a forgotten password by themselves.

## E-mails sent

| Trigger | Template |
|---|---|
| E-mail verification (sign-up, import, resend by an administrator) | `verify-email.eml` |
| "Forgot your password?" | `reset-password.eml` |
| Magic-link sign-in | `magic-link.eml` |
| One-time code sign-in | `email-otp.eml` |
| Invitation to an organization | `org-invitation.eml` |
| E-mail address change | `change-email.eml` |

Every template can be overridden, globally or per application: see [Custom templates](/docs/guides/administration/custom-templates).

Sending is rate limited per client (`MAIL_003`, `429`), as are the sign-in and password reset endpoints (`RATE_001`). Mailing a large user base at once, for example after a [migration](/docs/guides/migration/okta), should be spread over time.

## Testing locally

The Compose file ships a mail catcher behind the `mail` profile:

```sh
docker compose --profile mail up -d
```

```dotenv
SMTP_HOST=mailpit
SMTP_PORT=1025
```

Every message sent by the stack then shows up in the Mailpit web interface at `http://localhost:8025`.
