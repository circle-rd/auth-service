---
title: Managing applications
description: Create and configure OAuth 2.1 client applications via the admin API.
---

Every OAuth 2.1 client you integrate with Auth Service is represented as an **application** record in the database. Applications hold the OIDC client configuration — redirect URIs, allowed scopes, MFA policy, and registration settings.

All application endpoints require an active session with the `admin` or `superadmin` role. Requests without a valid session cookie receive `401 AUTH_001`.

The same operations are available in the admin interface:

![Applications list](/screenshots/applications.png)

## Create an application

```sh
POST /api/admin/applications
Content-Type: application/json

{
  "name": "My App",
  "slug": "my-app",
  "description": "Optional description",
  "redirectUris": ["https://app.example.com/callback"],
  "allowedScopes": ["openid", "profile", "email", "roles", "permissions", "features"],
  "isActive": true,
  "skipConsent": false,
  "isMfaRequired": false,
  "allowRegister": false,
  "url": "https://app.example.com",
  "icon": "https://app.example.com/icon.png"
}
```

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | string | required | Display name (1–100 chars) |
| `slug` | string | required | URL-safe identifier used as `client_id` (lowercase alphanumeric + hyphens, 1–64 chars) |
| `description` | string | — | Optional description (max 500 chars) |
| `redirectUris` | string[] | `[]` | Allowed redirect URIs for the OAuth flow |
| `allowedScopes` | string[] | `["openid","profile","email"]` | Scopes this application may request |
| `isActive` | boolean | `true` | Whether the application accepts new authorizations |
| `skipConsent` | boolean | `false` | Skip the consent screen for trusted first-party apps |
| `isMfaRequired` | boolean | `false` | Block token issuance for users without MFA enabled |
| `allowRegister` | boolean | `false` | Whether the application's sign-in page offers registration, and whether a sign-up that names it (`client_id`) may create an account. See [Registration](/docs/guides/administration/custom-templates#registration) |
| `isPublic` | boolean | `false` | `true` for a public client (browser or native app, PKCE only, no secret); `false` for a confidential client with a `clientSecret`. Set at creation, immutable afterwards |
| `isSystem` | boolean | `false` | Infrastructure application (hidden from the admin list by default, cannot be deleted). Superadmin only |
| `url` | string | — | Application home URL. Also the application's resource identifier (RFC 8707 `resource`) |
| `allowedResources` | string[] | `[]` | Protected resources (URLs of other applications) this application may request tokens for. Unknown URLs are rejected with `APP_001` |
| `enableEndSession` | boolean | `false` | Lets the application call `/api/auth/oauth2/end-session`. The call ends the central SSO session for **all** applications (there is no per-application logout), so leave it off for applications that only sign the user out locally |
| `postLogoutRedirectUris` | string[] | `[]` (seeded with `<url>/` when `url` is set at creation) | URLs accepted as `post_logout_redirect_uri` by end-session. Matching is strict, query string included |
| `enabledSocialProviders` | string[] \| null | `null` | `null` inherits the providers enabled on the server, `[]` disables social sign-in for this application, a list restricts it to those providers |
| `metadata` | object | `{}` | String key/value pairs (identifier keys, values up to 256 characters) added to the application's tokens as custom claims. Names reserved by the token (`sub`, `aud`, `iss`…) are rejected |
| `icon` | string | — | Icon URL (displayed in admin and consent screen) |

The response includes the auto-generated `clientId` (same as `slug`) and, for confidential applications, the `clientSecret`. **The secret is shown only once** — store it immediately.

## List applications

```sh
GET /api/admin/applications
```

Returns all applications with their OAuth client metadata, roles, active user count, and plan summary.

## Get a single application

```sh
GET /api/admin/applications/:id
```

## Update an application

```sh
PATCH /api/admin/applications/:id
Content-Type: application/json

{
  "isMfaRequired": true,
  "skipConsent": true
}
```

All fields from the create schema are accepted, except `slug` (immutable after creation).

## Rotate the client secret

```sh
POST /api/admin/applications/:id/rotate-secret
```

Generates a new random `clientSecret`, hashes it with SHA-256, and stores the hash. The plaintext secret is returned once in the response. All existing sessions using the old secret will fail at the next token refresh.

## Delete an application

```sh
DELETE /api/admin/applications/:id
```

Returns `409 APP_004` if any users still have an active `userApplications` record for this application. Remove user access first.

## Grant a user access to an application

```sh
POST /api/admin/applications/:id/users
Content-Type: application/json

{
  "userId": "<uuid>",
  "roleId": "<uuid>"   // optional — assigns a role immediately
}
```

If a default subscription plan exists for the application, it is assigned automatically.

## Update a user's access record

```sh
PATCH /api/admin/applications/:id/users/:userId
Content-Type: application/json

{
  "isActive": false,
  "roleId": "<uuid>",
  "subscriptionPlanId": "<uuid>"
}
```

## Revoke a user's access

```sh
DELETE /api/admin/applications/:id/users/:userId
```
